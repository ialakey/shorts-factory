# 🎬 AI Video Clipper

[English](README.md) · **Русский**

**Длинное видео → вертикальные Shorts.** Отбор моментов по композиции сигналов вместо «спросить у LLM»,
плюс виртуальная камера, которая кадрирует 9:16 как живой оператор. Всем управляет один `config.yaml`.

Конвейер коротких вертикальных роликов, управляемый конфигом. На вход — длинный эпизод,
на выходе — готовые клипы 9:16 с виртуальной камерой, пословными субтитрами, водяным знаком,
очищенными метаданными и отправкой в Telegram.

Вся система декларативная: поведение канала описывается одним `config.yaml`,
а список `pipeline` внутри него включает и выключает этапы.

```
эпизод.mp4  →  транскрипт  →  сигналы (аудио / лица / склейки / темп / hooks)  →  LLM-отбор моментов
            →  монтажная сборка сегментов  →  виртуальная камера 9:16  →  слои (субтитры, ватермарк, музыка)
            →  пересборка метаданных  →  Telegram
```

> **Это витринная ветка.** Урезанное MVP большого приватного проекта: оставлен путь
> «скачал → смонтировал → отдал», всё остальное вырезано (автозагрузка на YouTube/TikTok,
> планировщик публикаций, контур аналитики). Все параметры конфигурации сброшены к нейтральным
> значениям; в репозитории нет ни ключей, ни доступов, ни чужих медиафайлов.

## 🧭 Зачем это всё

Нарезать Shorts руками не сложно. Это долго, причём долго так, что с опытом быстрее не становится:
посмотреть 24 минуты серии, найти те два момента, которые работают без окружающего контекста, вырезать
их, перекадрировать 16:9 под экран телефона, разложить субтитры по словам, отрендерить. Примерно час на
клип, и почти всё это — механика.

Первая очевидная попытка была отдать транскрипт языковой модели и попросить лучшие моменты. Результат
стабильно не годился. Модель выбирает реплики, которые работают только если ты видел серию, путает
громкое с драматичным и не представляет, как сцена выглядит после кропа в вертикаль. Наращивание
промпта не помогало, потому что дело было не в формулировках — модели задавали вопрос, на который
транскрипт не отвечает.

Сработало другое: перестать требовать от одной модели правоты во всём. Сцена сначала описывается по
нескольким независимым осям — плотность речи, пики звука, присутствие лиц, монтажные склейки, темп,
hooks, — и окна-кандидаты детерминированно ранжируются **до** того, как модель их увидит. Дальше модель
делает ровно то, в чём действительно хороша: судит, интересен ли момент, и больше ничего. А то, что
она вернула, жёстко проверяется после: длительности пересчитываются по сегментам, границы притягиваются
к паузам речи и склейкам, всё, что не влезло в диапазон, отбрасывается.

Вертикальное кадрирование оказалось задачей той же формы. Центровой кроп выбрасывает половину кадра, а
наивное следование за найденным лицом даёт камеру, которая дёргается на каждой детекции — смотреть это
физически неприятно. Помогло перестать считать это задачей детекции и начать моделировать саму камеру:
демпфированный осциллятор, догоняющий отфильтрованную цель, с мёртвой зоной, лимитом скорости,
предиктивным упреждением, смещением по правилу третей и Ken Burns-дрейфом на случай, когда вести
вообще некого.

Последний вывод оказался не алгоритмическим, а эксплуатационным. Пайплайн, в котором падение на девятом
этапе стоит тебе первых восьми, — это пайплайн, который никто не будет итеративно крутить. Поэтому
каждый этап пишет явный промежуточный артефакт, каждая необязательная зависимость деградирует вместо
исключения, этапы включаются и выключаются по отдельности, а debug-режим гоняет любой отдельный этап по
песочнице. Отсюда же и один `config.yaml` вместо флагов командной строки: основная работа здесь —
подбор параметров, а подбору нужен файл, который можно диффать.

## 🚀 Быстрый старт

### Требования

- **Python 3.12+**
- **`ffmpeg` и `ffprobe` в `PATH`** — вызываются напрямую как команды из `ingestion/transcriber.py`,
  `analysis/audio_analyzer.py` и `publishing/spoof_metadata.py`. Бинарник внутри `imageio-ffmpeg`
  не подходит: в нём нет `ffprobe`.
- **`OPENAI_API_KEY`** — проверяется на уровне импорта `config.py`, без него приложение не стартует.

### Установка

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Установка ffmpeg:

```bash
winget install Gyan.FFmpeg   # Windows
brew install ffmpeg          # macOS
sudo apt install ffmpeg      # Debian/Ubuntu
```

После установки перезапустите терминал и проверьте: `ffmpeg -version`, `ffprobe -version`.

### Переменные окружения

```bash
cp .env.example .env
```

```ini
OPENAI_API_KEY=sk-...     # обязателен
TELEGRAM_BOT_TOKEN=       # опционально — только для этапа telegram_notify
TELEGRAM_CHAT_ID=
ANIMEGO_MIRROR=           # опционально — зеркало AnimeGO, если основной домен заблокирован
ANIME_DL_PROXY=           # опционально — прокси для этапа скачивания (http:// или socks5://)
```

`.env` в `.gitignore`. **Ни один токен не читается из `config.yaml`** — секреты живут только в окружении.

### Запуск

```bash
python app.py
```

`app.py` проверит и при необходимости создаст структуру каталогов всех каналов в `channels/`,
затем прогонит каждый валидный канал по его `pipeline`. Падение одного канала не роняет остальные:
исключение логируется, канал попадает в итоговый список ошибок.

> **Windows / PyCharm:** запускать нужно интерпретатором **этого** проекта (`.venv\Scripts\python.exe`),
> иначе получите `ModuleNotFoundError: No module named 'yaml'`. Рабочая директория — корень репозитория.

```

├── config.yaml

├── output_clips/          # готовые клипы
├── assets/
│   ├── backgrounds/       # нужны, только если use_blurred_background: false
```

Недостающие папки и базовый `config.yaml` (из `DEFAULT_CONFIG` в `config.py`) создаются автоматически.

В `channels/DemoChannel/assets/` лежит один открытый шрифт и больше ничего: музыку и фоны нужно
принести свои — репозиторий намеренно не содержит чужих лицензионных материалов.

## ⚙️ Этапы pipeline

Список этапов задаётся в `channels/<Channel>/config.yaml → pipeline`.

| Этап | Модуль | Что делает |
|---|---|---|
| `kodik_download` | `ingestion/autodownload.py` | Скачивает эпизоды по списку тайтлов через [anime-dl-core](https://github.com/ialakey/anime-dl-core) (legacy-имя `autodownload` поддерживается) |
| `transcribe_video` | `ingestion/transcriber.py` | Извлекает первую аудиодорожку через ffmpeg (16 kHz mono PCM) и распознаёт её Whisper'ом |
| `analyze_moment` | `analysis/gpt_analyzer.py` | Собирает мультисигнальный payload и получает от LLM список моментов с сегментами |
| `make_clips` | `rendering/video_editor.py` | Режет и склеивает сегменты, собирает финальное полотно 1080×1920 |
| `dynamic_shorts` | `rendering/face_detector.py` | Виртуальная камера: кадрирование 9:16 с ведением по лицам |
| `watermark` | `rendering/layers/watermark_renderer.py` | Текстовый водяной знак с тенью и прозрачностью |
| `enhance_audio` | `rendering/audio/enhancer.py` | Soft-knee компрессия оригинальной дорожки, подтягивание тихих мест |
| `video_effects` | `rendering/video_editor.py` | Зеркало, насыщенность, гамма, контраст, ресайз, FPS, скорость |
| `music` | `rendering/video_editor.py` | Подмешивает случайный трек из `assets/musics` |
| `subtitles` | `rendering/layers/subtitle_renderer.py` | Повторная транскрибация клипа, LLM-чистка текста, рендер по словам с `<hl>`-выделением и цветными эмодзи |
| `title` | `rendering/layers/title_renderer.py` | Титр с автоподбором размера шрифта |
| `spoof_metadata` | `publishing/spoof_metadata.py` | Полная очистка метаданных и пересборка контейнера |
| `telegram_notify` | `publishing/telegram_notifier.py` | Отправляет новые клипы медиагруппой в чат |

**Важные нюансы:**

- `pipeline` работает как **набор флагов включённых этапов, а не как порядок исполнения**:
  фактический порядок зашит в `channel_processor.py` и `make_clips()`.
- Если включён хотя бы один «фичевый» этап (`dynamic_shorts`, `video_effects`, `speed`, `watermark`,
  `enhance_audio`, `music`, `subtitles`, `title`), то работают **только** перечисленные в `pipeline`
  — остальные выключаются, даже если у их секции стоит `enabled: true`.
- Если включены пост-клиповые этапы, но `make_clips` в `pipeline` нет, он **запустится автоматически** —
  иначе применять эффекты было бы не к чему.
- `spoof_metadata` удаляет оригинал только после успешной пересборки контейнера: при падении ffmpeg
  клип не теряется.
- `telegram_notify` отправляет только **новые** файлы — список `*.mp4` фиксируется до обработки видео.

## 🎯 Как выбирается момент

Разбор — в статье [«Почему LLM + транскрипт почти всегда дают мусор»](https://habr.com/ru/articles/1021552/).

Наивная схема «скормить транскрипт модели» проваливается: LLM выбирает реплики, которые работают
только в контексте всей серии, путает громкость с драмой и не видит, как сцена выглядит в вертикали.

Поэтому `analysis/gpt_analyzer.py` отдаёт модели не сырой текст, а **предобработанное описание сцены
по осям**:

| Сигнал | Источник | Что извлекается |
|---|---|---|
| **Речь** | Whisper | Сегменты с таймкодами, плотность слов |
| **Аудио** | `analyze_audio_peaks` | RMS, zero-crossing rate, spectral centroid, события-пики с метками силы |
| **Лица** | `analyze_face_activity` | Интервалы присутствия лиц, их количество, максимальная доля кадра |
| **Визуал** | `_detect_cuts` + `_build_visual_summary` | Смены сцен по разнице кадров, интенсивность движения |
| **Темп** | `_build_tempo_windows` | Окна по 5 с: речевая плотность, паузы, склейки |
| **Эмоции** | `_extract_emotion_peaks` | Пересечение текстовых маркеров с аудиопиками |
| **Hooks** | `_extract_hooks` | Незакрытые вопросы, обещания, конфликты |

Эти сигналы детерминированно ранжируются в `analysis/moment_scorer.py` ещё до того, как их увидит LLM,
так что в промпт уходит только верхушка списка кандидатов — это дешевле и заметно стабильнее, чем
свободный отбор.

Дальше — **жёсткая валидация уже после ответа модели** (`analysis/moment_validator.py`): `duration`
каждого момента пересчитывается как сумма его сегментов, границы притягиваются к паузам речи и
монтажным склейкам, моменты вне диапазона `gpt.min_time`–`gpt.max_time` отбрасываются. Если после
фильтрации не осталось ничего — запрос повторяется (до 3 попыток) с уточняющим суффиксом. Сетевые
ошибки, rate limit и 502 ретраятся с нарастающей паузой; невалидный JSON и протухший токен падают сразу.

Момент — это **монтажная сборка**: `segments` могут браться из разных частей эпизода, паузы вырезаются,
hook всегда в первом сегменте, последний — cliffhanger или петля к началу.

Полный payload, отправленный модели, сохраняется рядом с клипами в `<video>_chatgpt_payload.txt` — это
тот самый «явный промежуточный артефакт», без которого отлаживать выбор моментов невозможно.

## 🎥 Виртуальная камера (`dynamic_shorts`)

Разбор — в статье [«Я научил виртуальную камеру быть оператором»](https://habr.com/ru/articles/1021278/).

Центровой кроп 16:9 → 9:16 теряет половину кадра, а наивное следование за лицом даёт дёрганую камеру.

```
детекция → трекинг → стабилизация → виртуальная камера → интерполяция → кроп
```

1. **Каскад детекторов** (`_DetectorBackend`): **MediaPipe** → **YuNet** (ONNX через OpenCV) →
   **Haar Cascade**. Отказ любого бэкенда не ломает этап.
2. **Трекинг** — nearest-neighbour по `match_tolerance` с grace-периодом `max_miss_time`:
   кратковременная потеря лица не приводит к прыжку камеры.
3. **Стабилизация** — anti-jerk (жёсткий лимит скачка между кадрами) + low-pass фильтр `face_filter`.
4. **Камера как демпфированный осциллятор**: `follow_stiffness` (упругость штатива),
   `follow_damping` (демпфирование), `max_center_speed` / `max_center_accel` (лимиты),
   `predictive_lead` (оператор смотрит чуть вперёд), `human_lag` (микролаг, «живое» движение).
5. **Правила композиции**: `side_bias` / `side_bias_strength` (rule-of-thirds),
   `eye_level_lift` (целимся на глаза, а не в центр лица), `center_dead_zone` (игнор микродвижений),
   `face_margin` (зазор до краёв).
6. **Ken Burns как fallback**: когда лиц нет, камера не замирает, а мягко панорамирует и зумит
   (`ken_burns_*`; амплитуды можно обнулить, чтобы просто зафиксировать кадр).
7. **Интерполяция**: анализ идёт на `analysis_fps` (по умолчанию 8 к/с), состояния камеры
   интерполируются на полную частоту кадров, после чего вычисляется ROI и применяется кроп.

| `video` | Размер итогового полотна (по умолчанию 1080×1920) |
| `background` | Размытый фон из исходника (`use_blurred_background`, `blur_strength`) либо статичная картинка / прозрачное окно PNG; `fit_mode: contain` или `cover` |
| `dynamic_shorts` | Все параметры детекции, трекинга, физики камеры, композиции и Ken Burns |
| `watermark` | Текст, цвет, размер, прозрачность, тень, позиция, отступы |
| `video_effects` | `mirror`, `color_saturation`, `gamma`, `contrast`, `resize`, `frame_rate` (число или `random`), `speed` |
| `audio_enhancer` | Компрессор: `threshold`, `ratio`, `soft_knee`, `makeup_gain`, `noise_floor`, `output_ceiling` |
| `music` | Громкость подмешиваемого трека относительно оригинала |
| `subtitles` | Шрифт, цвет, обводка, тень, выравнивание, `words_per_chunk`, стиль `<hl>`-выделения, модели Whisper и LLM, промпты (`normal` / `meta_ad`) |
| `moment_scoring` | Веса сигналов и отбор кандидатов до похода в LLM |
| `moment_validation` | Притягивание границ и правила отбраковки после LLM |
| `gpt` | Модель, диапазоны `min_time`/`max_time` и `min_count`/`max_count`, аудитория, платформа, тон и главный промпт отбора моментов |
| `kodik_download` | Список тайтлов вида `["Название", "1-3", "Студия озвучки"]`; дальше два необязательных поля — максимальное качество и имя плеера: `["Название", "1-3", "Студия", 720, "kodik"]` |

Про субтитры отдельно: при `improve_transcript_quality: true` клип **переразпознаётся** более тяжёлой
моделью (`enhanced_whisper_model`), затем текст чистится через LLM (`enhancer_model`) — правится
орфография, и ровно одно ключевое слово оборачивается в `<hl>…</hl>`, которое рендерер красит отдельным
стилем. Цветные эмодзи рендерятся через Pilmoji, шрифт задаётся `emoji_font_path`.

## 🧪 Debug-режим

`debug: true` в конфиге канала:

- вход берётся из `test_data/`, выход пишется в `output_test_data/`;
- этап скачивания отключается;
- сохраняются промежуточные артефакты: `<video>_transcript.txt`, `<video>_moments.json`,
  `<video>_chatgpt_payload.txt`;
- если моменты не считались, а пост-клиповые этапы включены — берётся весь ролик целиком,
  чтобы можно было отлаживать субтитры, ватермарк и эффекты по отдельности.

Это прямое следствие принципа из первой статьи: каждый этап должен отлаживаться независимо,
без пересчёта всех остальных.

## ✅ Тесты и CI

```bash
pip install -r requirements-ci.txt

pytest                    # весь набор (~60 c)
pytest -m "not render"    # быстрый слой, без реального рендера (~30 c)
pytest -m render          # только этапы, которые реально рендерят клип (~28 c)
```

Тесты герметичны: OpenAI, Telegram и скачивание эпизодов замоканы, модуль `whisper` подменяется
заглушкой в `tests/conftest.py` (иначе CI тянул бы torch и качал модели). `mediapipe` намеренно не
ставится в CI — код обязан деградировать на fallback-детекторы, и это тоже проверяется.

## 📤 Доставка

- **Telegram** работает из коробки при заданных `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`: новые клипы
  уходят медиагруппой с названиями моментов и нормализованным именем тайтла.
- **`spoof_metadata`** пересобирает контейнер без перекодирования (`-c copy`), полностью стирает
  исходные метаданные (`-map_metadata -1`) и подставляет вместо них правдоподобные данные редактора.
- **Автозагрузки на YouTube и TikTok в этой ветке нет.** Она осталась в приватном проекте; витрина
  заканчивается на «готовый клип на диске, отправленный в Telegram».

## ⚠️ Известные ограничения

- `OPENAI_API_KEY` обязателен даже для сценариев без LLM — проверка стоит на импорте `config.py`.
- Используется **legacy-API** `openai==0.28.0` (`openai.ChatCompletion`), а не актуальный SDK.
- Аниме-сайты у многих провайдеров заблокированы: перед запросом проверяется резолв `animego.org`,
  при недоступности этап мягко пропускается и пайплайн продолжает работать с уже скачанными видео.
  Обходится через `ANIMEGO_MIRROR` и `ANIME_DL_PROXY`.
- Плееры ломаются без предупреждения, поэтому этап перебирает все плееры, которые сайт отдал для
  серии, и останавливается на первом рабочем. Поток `hls`/`dash` собирается в mp4 через ffmpeg.
- `pilmoji 2.0.4` требует `emoji 1.x` — версия зафиксирована в `requirements.txt`, не обновляйте вслепую.
- Whisper-модели скачиваются при первом запуске; `large-v3-turbo` заметно тяжелее `base`.

## 🔁 Рекомендуемый workflow

1. Прочитать [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) и статьи выше.
2. Создать канал в `channels/`, наполнить `assets/` (шрифты, музыка, при необходимости фоны).
3. Прогнать отладочный запуск на `test_data/` с `debug: true` и посмотреть промежуточные артефакты.
4. Переключить `debug: false`, положить эпизоды в `input_videos/`, запустить `python app.py`.
5. Проверить результат в `channels/<Channel>/output_clips/`.
